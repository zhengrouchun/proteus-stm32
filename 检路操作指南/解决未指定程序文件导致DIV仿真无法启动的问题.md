# 解决未指定程序文件导致DIV仿真无法启动的问题

日志中的`Program file is not specified`是本次启动失败的明确原因，随后`Real Time Simulation failed to start`是结果。网表编译、链接成功，不能证明固件已配置或测量已开始。

我此前让你保留U1后直接运行电压表，遗漏了关键前提：**工程里存在STM32F103C8模型，就必须给它有效的程序文件。即使U1与分压电路没有连线、断开供电或移到图纸边框外，模型仍在工程中，依然可能阻止整个仿真启动。**这项说明已修正。

## 先让三工况能测量

1. 停止仿真，关闭报错窗口。
2. 用`File → Save As`另存副本，例如`解决无程序文件时DIV三工况无法启动.pdsprj`，保留原完整工程。
3. 在测试副本中删除U1和其专用复位、BOOT0及3.3V线路，仅保留左侧BAT1=1V、Rs/R5=2kΩ、R1=R2=10kΩ、两只SW-SPST、电压表和GND。不用的EEPROM、OLED等也从测试副本移除。
4. 不要仅断开U1连线。确认测试副本中已经没有U1或其他需要固件的MCU模型。
5. SW1闭合、R2跨接开关断开，启动仿真并检查日志，然后记录正常VA约0.909V、VB约0.455V。
6. 断开SW1，记录R1断路VA约1V、VB约0V。
7. 恢复SW1闭合，再闭合R2跨接开关，记录R2短路VA约0.833V、VB约0V。

这些数值是理论核对值；仿真启动后才能记录实测。电压表的`+88.8`画面不能当作实际电压。

## 保留U1的完整工程怎么启动

打开原完整工程，用CubeMX配置芯片、HSI8MHz及ADC，写程序并编译得到针对STM32F103C8的有效HEX。双击U1，把`Program File`设为HEX实际路径，时钟属性与固件一致，再运行。空文件、其他芯片的HEX或仅填路径不能替代有效固件。先处理日志中明确的缺程序错误，再根据新日志排查后续问题。

## 本次依据与修正

读取用户提供的仿真日志和报错截图，定位第一条红色错误`Program file is not specified`。用`rg -n`检索此前说明中的“先不要连U1”“不加载程序也可以”等表述，补充纯模拟测试必须移除无固件MCU的前提；将首轮DIV图改为不含MCU的独立电路。使用本地Pillow渲染并查看核对。修改的是操作说明和参考图片，尚未修改用户Proteus工程或运行实际仿真。
