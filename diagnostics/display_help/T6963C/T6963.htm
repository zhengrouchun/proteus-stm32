GRAPHICAL LCD (T6963)

Introduction

LCDPIXEL.DLL can be used to simulate commonly available pixel addressable LCD display modules based around the Toshiba T6963C controller chip. Support for other controller chips may be added in the future - please tell us what you are using.

A number of common display types from Densitron and Powertip are pre-defined in DISPLAYS.LIB.

The T6963C Datasheet contains details of how to program the controller chip.

Symbol Naming

The ISIS library part should be created with two active symbols representing the on and off states of the display backlight. The origin should be at the top left corner of the symbols; their area defines where the display output will appear.

Pin Naming

The model should have pin names corresponding to the pins of the T6963C controller - the easiest thing to do when making a new display is to decompose one of the existing ones.

Special provision is made for dealing with the FS (font-select) and MD (mode select) pins which may, or may not, be presented on the display module connector. See below.

Properties

The LCDPIXEL model supports the following properties:

Property Default Description

WIDTH

-

Specifies the display width in characters.

HEIGHT

-

Specifies the display height in characters.

CLOCK

250kHz

Specifies the clock frequency of the controller chip. This determines the time taken to process the various commands.

FS0,FS1

-

Specifies a hard wired logic state for the font select pins of the controller chip. Use these properties if either of the font select pins is not present on the LCD module connector

MD2,MD3

-

Specifies a hard wired logic state for the column width select pins of the controller chip. Use these properties if either of the width select pins is not present on the LCD module connector.

RAMSIZE

65536

Specifies the amount of RAM present on the LCD module. Address outside the RAM size are assumed to 'wrap round' into the physically memory space.

Debug Support

The controller model supports a trace mode which logs all commands sent to the display. This enables you to verify what commands are being received by the controller as program execution proceeds.

Debug messaging can be enabled manually from the Debug  menu in ISIS. When enabled internal trace data for the model will be dumped in the simulation log during a simulation run.

Bear in mind that enabling trace mode may send a great deal of data to the simulation log, and seriously degrade the performance of the simulator.

Limitations

The T6963C model has the following limitations:

  • The timing for many commands is not specified in the data sheet; we have assumed that all command and argument loads take 16 clock cycles. If you your code does not check the status register as specified in the data sheet, it may not work properly on a physical display module.

  • The operation of the screen peek and screen copy commands is very badly documented; we have tested some 3rd party code that uses screen peek, but we cannot be certain about the exact behaviour of these commands in more obscure situations (e.g. text attribute mode).

  • The clock frequencies used on the specific display modules in DISPLAYS.LIB are not given in the data sheets, so we have estimated clock frequencies assuming a 60Hz refresh rate.

  • Dual scan mode is not supported.

  • The action of the HALT pin is not modelled.
