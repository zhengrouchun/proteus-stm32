# 解决按键松开切换双闪与交替闪烁及消抖

## 问题与原因

临时排线测试程序直接用 PB0 当前电平控制 PA1、PA2，因此按住时 LED 亮，松开后 LED 灭。它没有记住闪烁模式，也没有在松开时切换模式。旧示例中的 `HAL_Delay()` 和等待按键松开的 `while` 会阻塞主循环；机械触点抖动还可能让一次操作被当成多次。

电路中按键 PB0 按下接地并使用上拉；两个 LED 经电阻接电源，由 PA1、PA2 拉低点亮。因此按住时要把 PA1、PA2 设为高电平，闪烁亮相时才设为低电平。

## 参考图片的代码在做什么

- `while (1)` 让程序不断重复检查按键和控制 LED。
- `HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin) == GPIO_PIN_RESET` 判断按键是否按下，因为这个按键按下时为低电平。
- `keyflag++` 每检测到一次按下就加一。紧接着的 `while (按键仍按下);` 一直等待松开，使同一次长按不会在主循环里反复加一；但它会阻塞程序。
- `if (keyflag == 3) keyflag = 1;` 使模式按 1、2、1、2 循环。
- `keyflag == 1` 时先把两路 LED 都拉低点亮，等待 200 ms，再都拉高熄灭，等待 200 ms，即同步闪烁。
- `keyflag == 2` 时先让 LED1 灭、LED2 亮，等待 200 ms，再让 LED1 亮、LED2 灭，等待 200 ms，即交替闪烁。
- 图片没有消抖；`HAL_Delay(200)` 与等待松开的 `while` 都会使主循环暂时不能处理其他工作，而且图片在按下时就改变 `keyflag`，与本项目要求的“松开后切换”不同。

## 处理流程

1. 根据电路确认 PB0 为低电平按下，PA1、PA2 为低电平点亮。
2. 核对工程 TIM2 配置：8 MHz 定时器时钟，`PSC=7`、`ARR=999`，更新中断每 1 ms 发生一次；工程中已有 TIM2 中断入口、NVIC 使能和 `HAL_TIM_Base_Start_IT(&htim2)`。
3. 在 TIM2 周期回调中每毫秒读取 PB0。新电平连续出现 20 次才被认可，按下和松开都参与消抖。
4. 只在一次有效按下之后的有效松开切换模式：首次为双灯同步闪烁，再次为两灯交替闪烁，之后循环切换。每次切换重置 200 ms 闪烁相位。
5. 按下阶段要求两灯熄灭。主循环按参考图的 `keyflag==1`、`keyflag==2` 分支写 GPIO；TIM2 中断只负责按键消抖、模式计数和 200 ms 节拍。

## 修改位置与所用方法

- `06Ledcontrol/Core/Src/main.c` 的 `USER CODE BEGIN PV`：增加 `led_keyflag`、`led_button_pressed`、`led_blink_phase`。它们由 TIM2 中断更新、主循环读取，所以声明为 `volatile`。
- 同文件的 `USER CODE BEGIN 0`：增加 `HAL_TIM_PeriodElapsedCallback()`，每 1 ms 采样 PB0，连续 20 次相同才确认按下或松开；有效松开后执行与图片相同的 `keyflag++` 和到 3 回到 1；每 200 ms 改变一次闪烁相位。
- 同文件的 `USER CODE BEGIN 2`：初始化结束后将 PA1、PA2 置高，保证第一次有效松开前 LED 熄灭。原有定时器启动语句继续使用。
- 同文件的主循环：停用此前的按键与 LED 实验代码，按 `led_keyflag==1` 同步闪烁、`led_keyflag==2` 交替闪烁；按钮按住时强制熄灭，末尾用 `__WFI()` 等待中断。
- `06Ledcontrol/Core/Src/tim.c`：读取并核对 `PSC` 和 `ARR`，未修改。
- `06Ledcontrol/Core/Src/gpio.c`：读取并核对 GPIO 输入、输出及上拉配置，未修改。
- `06Ledcontrol/Core/Src/stm32f1xx_it.c`：核对 TIM2 IRQ 调用 HAL 处理函数，未修改。

所用 HAL/CMSIS 调用包括 `HAL_TIM_Base_Start_IT()`、`HAL_TIM_PeriodElapsedCallback()`、`HAL_GPIO_ReadPin()`、`HAL_GPIO_WritePin()` 和 `__WFI()`。源码使用 `apply_patch` 修改。终端读取与构建工具当前因 `helper_unknown_error: setup refresh had errors` 无法启动，因此尚未执行编译或 Proteus 仿真；已通过补丁匹配核对配置行和新增代码位置。

## 相比原代码的好处

- 只在完整、稳定的“按下再松开”后切换一次模式，减少抖动引起的重复切换。
- 按住时保持熄灭，松开后从确定的第一相位开始闪烁，模式不会依赖按键保持时间。
- 用 TIM2 中断计时取代阻塞式 `HAL_Delay()` 和等待松开的 `while`，主循环可以在灯态不变时休眠。
- 主循环按模式直接控制两灯，中断内部只做短时间的采样和计数，不使用阻塞式等待。

## 新代码按执行顺序解释

1. `led_keyflag` 对应图片中的 `keyflag`：上电为 0；第一次有效松开变为 1；第二次变为 2；再加到 3 时改回 1。
2. `HAL_TIM_PeriodElapsedCallback()` 由 TIM2 每约 1 ms 调用一次。它读取 PB0：低电平为按下，高电平为松开。
3. `last_sample` 是上一毫秒读到的电平，`same_sample_count` 是连续相同的次数，`confirmed_level` 是已完成消抖的状态。连续 20 次相同才确认按下或松开。
4. 确认按下时先记录 `valid_press_seen=1`；确认松开且确实按下过时才执行 `led_keyflag++`，所以每次完整操作只改变一次模式。按住时用 `led_button_pressed=1` 让主循环熄灯。
5. `blink_elapsed_ms` 每次 TIM2 中断加 1，到 200 时清零并改变 `led_blink_phase`。这对应图片中每次 `HAL_Delay(200)` 结束后进入下一次亮灭状态，但不会堵住主循环。
6. 主循环先检查 `led_button_pressed`，按住就把 PA1、PA2 拉高使两灯灭。松开后，`led_keyflag==1` 时两灯一起亮灭；`led_keyflag==2` 时 LED1、LED2 交替亮。`led_keyflag==0` 时保持熄灭。
7. `__WFI()` 让主循环等待下一次中断。`volatile` 保证主循环读取中断更新后的 `led_keyflag`、`led_button_pressed` 和 `led_blink_phase`。

`uint8_t` 是 8 位无符号整数，`uint16_t` 是 16 位无符号整数；`static` 局部变量在下一次中断到来时仍保留数值。`#if 0` 到 `#endif` 之间的旧实验代码不参与编译。

## 上板或仿真时的检查

重新构建工程并让 Proteus U1 的 Program File 指向最新的 `.hex` 或 `.elf`。确认 BOOT0 接地、PB0 配置上拉、TIM2 中断已启用。预期现象：上电全灭；第一次按下仍全灭，松开且稳定约 20 ms 后双闪；第二次按下全灭，松开后交替闪烁。
