# 解决隐藏电源轨与九工况程序缺失的问题：原因、过程、证据

本次只处理截至 2026-10-11 的 DIV 阶段。已完成软件扩展、真实 Keil 编译、PC 逻辑测试及工程电源轨文本修正；尚未执行 Proteus 图形界面运行与实际 ADC 测量。

## 一、关键卡点及原因

### 1. 图上标注 3.3V，但隐藏 VDD 所属电源轨实际配置为 5V

读取 `DIV_protues_电路图\DIVject.pdsprj` ZIP 容器内 `SCRIPTS/PWRRAILS.DAT`，实际发现：

```text
{VCC/VDD=5,POWER}
{3.3V=VCC/VDD}
{VDD=VCC/VDD}
{VSS=GND}
```

原因是电源端子名称与电源轨电压分开保存。“3.3V”被绑定到默认 5V 电源轨，隐藏 VDD 也绑定到同一轨，不能靠元件旁边显示的文字判断供电正确。显式 VDDA 另接 3.3V 电池，两类供电定义存在不一致。

解决：复制整个电路目录，生成新的问题命名工程，只把供电轨定义改为 `{VCC/VDD=3.3,POWER}`，保留绑定关系。重新读取容器验证 CRC，确认 ROOT.DSN、ROOT.CDB、GRAPHS.DAT、PROJECT.XML 均与原工程相同。日志在 `验证日志\电源轨修改验证.txt`。

边界：这证明工程文件配置已修改，**不能证明图形界面已复开、VDD 实际电压已测对，或用户遇到的所有运行问题都由此引起**。这些要在 Proteus 内核验。

### 2. 原工程只有真实 ADC 电压显示，没有九工况判别与测量记录

读取原 `Src\main.c`，发现已有 ConfigChannel→Start→PollForConversion→GetValue→Stop，PA0/PA1 映射正确且已校准。但只报告 VA/VB 和原码，没有 STATE、特征次数、转换次数、耗时、运行电源状态。独立参考 snippet 也未集成进完整工程。

解决：保留整个 CubeMX 工程、HAL/CMSIS、启动文件、MSP、中断、Keil 项目与 USER CODE 标记；在原 main.c 用户区扩展记录与报告，增加 `Inc\div_diagnosis.h` 存放原表九组区间、整数换算、唯一匹配函数。始终两点采集，正常必须同时满足 VA、VB。

### 3. 新固件要求 115200，而旧代码和终端仍为 9600

源码原值 `huart1.Init.BaudRate = 9600`，ioc 原值 `USART1.BaudRate=9600`，Proteus ROOT.DSN 中也实际找到 `{BAUDRATE=9600}`。

解决：源码和 ioc 均同步为 115200，已经编译。终端属性在二进制原理图内，没有可靠图形操作工具，因此**尚未修改**。教程要求双击终端设置 115200；否则装入新固件后可能看不到正常文字。

### 4. 原图缺少 R2 断路和 R1 短路的操作开关

用户截图已有 SW1（R1 断路）、SW2（R2 短路）、SW3（复位）；缺少 SW4、SW5。不能把 SW3 用于故障，也不能从循环编号推断故障。

处理：已给出 SW4 串接 R2 下端、SW5 只跨接 R1 两端的逐节点步骤，并要求 SW2 下端移至 R2_BOTTOM 使其严格并联 R2。**没有声称已绘制这两个开关**。九种单故障的正式接线应按操作说明完成并用网络高亮或网表核验。

### 5. PC 测试工具首次编译中文路径失败

初次 MSVC 测试批处理以本地字符编码写入，但当前命令行以不同编码解释中文路径，报 C1083 找不到源文件。将批处理明确设为 UTF-8 并先执行 `chcp 65001`，路径继续加引号，随后编译与 5800 组检查通过。没有移动、删除工程来规避中文目录。

## 三、关键代码怎样工作

1. `HAL_ADCEx_Calibration_Start`：初始化后只运行一次校准，失败先尝试串口报告再停机。
2. `ReadAdcChannel`：配置当前输入与采样时间，启动、等完成、读取真实 ADC 寄存器、计数、停止。失败也尝试停止；错误不会伪装成 0mV。
3. `DivCodeToMillivolts`：按 3300/4095 缩放，每个原码约对应 0.806mV；加入半个除数实现就近整数毫伏。程序没有任何理论电压替代采样。
4. `DivClassify`：以有符号数比较全部九个二维闭区间，匹配数量恰好为一才接受。保留负下界 -5，避免无符号比较造成零伏状态失配。
5. `RunDivDetection`：本轮记录清零，先读 VB 再读 VA；每次取得有效节点才加特征数，每次转换确认完成并取值才加转换数。停止失败仍保留已经发生的转换数，但不把该节点作为可靠判别输入。
6. `HAL_GetTick`：检测前后相减，使用无符号差值跨计时器回绕；毫秒精度可显示 0，UART 与 500ms 延时不在检测耗时中。
7. `SendReport`：输出 STATE/KIND、两路 RAW/MV、两个计数、耗时、RUN_POWER 与 ERROR。未有效读取的节点输出 NA；失败状态为 UNKNOWN，运行电源始终诚实报告 NOT_IMPLEMENTED。

新增与修改的应用语句在源文件旁均有中文解释，没有使用 `0U` 一类未经说明的应用字面量。`{0}` 表示将结构字段清零，注释已说明；0/1 在循环和有效标志中也注明含义。ST/CMSIS 依赖中的原有 `0U` 等标准无符号常量保留，避免为排版要求篡改厂商库。不是所有 HAL/CMSIS 库行都重写或翻译。
