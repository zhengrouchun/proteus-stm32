INTRODUCTION

The Proteus high performance PCB design system is an integrated part of the Proteus software suite and works seamlessly with the schematic capture software. It launches into a separate tab in the Proteus application and can then be separated into a seperate frame for those users who prefer to work with a side-by-side view.

There are two technologies in Proteus that facilitate the integration between schematic and layout, one for component/footprint data and the other for connectivity information. These are summarised below:

Common Database  

The schematic and layout modules share a common database (CDB) which contains information about all the parts and elements in the project. Parts represent the physical components on the PCB whilst elements represent the logical components on the schematic. The CDB also stores the 'binding' between elements and parts. The upshot of all this is that changes to one element (e.g PACKAGE property) of a multi-element part can now be reflected to the other elements automatically whilst changes to the part (in the layout) can be reflected to all the elements. Functions like pinswap, gateswap and back-annotation are much more robust whilst we have also made clearer the effect of changing part IDs (reannotation - all elements get a new part ID) as opposed to element IDs (rebinding - the connectivity is changed) within the schematic.

Live Netlist

Proteus 8 maintains a 'live' netlist enabling changes made on the schematic to be reflected on the layout, inside Design explorer and the Bill Of Materials in real time. Changes to the PCB are shown in such a way that they can still be rejected before components and tracking are actually removed from the layout. A batch mode (live netlisting off) is also available should you prefer to work that way.

This chapter primarily deals with the relationship and communication between the Proteus schematic and layout modules and is therefore likely to be of limited interest to users of only our simulation software.
