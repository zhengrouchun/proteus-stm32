Packaging Errors with Mixed Device Types

This error occurs because you are trying to package a number of elements of which one or more elements are homogeneous and one or more are heterogeneous.

Solution

First of all, check that the only devices highlighted on the schematic are those which you want to package. This normally happens if, for example, you are trying to package a simple, single element device (such as a resistor) but another element elsewhere on the schematic is highlighted.

Should this not be the case and you are trying to package a multi-element device, follow the instructions below according to the type of device you want to package.

Packaging Multi Element Homogeneous Parts:

  1. Highlight a single element.
  2. Click on the Make Device icon.
  3. Launch the Visual Packaging Tool from the Packaging screen on the Make Device wizard.
  4. Specify the number of elements via the No. of Gates field as shown below.

 

Packaging Multi Element Heterogeneous Parts:

  1. Place all the elements that make up the device ensuring that all elements are annotated correctly with a sequential sequence of element Ids (U1:A, U1:B, etc.) as is shown in the example below.

  2. Highlight all the elements of the device ensuring no other components are tagged.
  3. Click on the Visual Packaging Tool icon.
  4. Proceed with packaging in the normal way.

Error: Expected component element 'x' to be an instance of 'y' or a later device element.

Where ‘x’ is the element ID (A, B, C, etc.) that is in error and ‘y’ is the device name (library part name) that was expected.

Cause:

An element of a multi-element heterogeneous device is placed (i.e. is an instance of) a device that is not the same device or a later device to that used in the previous element.

Consider the generic case of a multi-element heterogeneous device consisting of elements U1:A, U1:B, U1:C, U1:D, etc. where each element is an instance of a device DEVICE:A, DEVICE:B, DEVICE:C and so on. It is a requirement that if, for example, U1:A is an instance of DEVICE:A, then U1:B (the next element) must either also be an instance of DEVICE:A or a later device (i.e. DEVICE:B, DEVICE:C, etc.). The same applies to U1:C in regard to U1:B, and so on.

Solution:

Re-annotate the elements such that moving through the elements (U1:A, U1:B, etc.) each element is the same or a later device to the device in the previous element.

Error: A tagged component with a reference 'x' (i.e. element 'y') was found but not expected.

Where ‘x’ is the component reference of the element that was found and ‘y’ is the actual element ID.

Cause:

This error occurs where the annotation of elements in a multi-element heterogeneous part are not sequential. In the example below, this error would occur for element ‘C’ ; given that only two elements are highlighted, an element ‘C’ is unexpected.

 

Solution:

Re-annotate the elements such that the annotation is sequential and consistent with the number of elements. In the example above , having two elements highlighted they should be annotated as RL1:A and RL1:B as shown below.

Packaging Errors with Pins

The Visual Packaging Tool has encountered problems with the pins on the device you are trying to package. Below is a listing of possible error messages and the steps you should take to correct the error.

Error: There are two more pins with the same name (‘x’) in legacy device ‘y’.The device cannot be packaged until it is re-made via the Make Device command (you do not need to rename the pins)

Where ‘x’ is the pin name that is duplicated and ‘y’ is the name of the device (library part) containing the duplicate pins.

Cause:

You have a device (created in an earlier version of the software ) in which more that one pin has the same name.

Solution:

Edit the pin names on the device (you may first have to decompose the part) such that each device pin has a unique name.

With Proteus it is possible to have more than one pin with the same pin name on a device and these pins are considered internally connected. This is useful if, for example, you want to want to wire ‘through’ a device and so would place one pin on either side of the device body. You must, however, remake the device in Proteus to avoid any possible legacy issues with older library parts.

We consider this functionality to be for advanced users of the software and should not be attempted if you are unsure of the consequences.

Error: Pin 'x’ found in two different heterogeneous devices (y and z). This is not allowed.

Where ‘x’ is the name of the pin and ‘y’ and ‘z’ are the two devices (library parts) that contain the pin.

Cause:

You are attempting to package a multi-element heterogeneous device where two or more different devices (library parts) that make up the overall device contain a pin with the same name.

Note that this error does not occur where you are making a multi-element heterogeneous device where two or more elements are instances of the same library part – for example, a relay consisting of a coil (an instance of RELAY:A) and two sets of contacts (two instances of RELAY:B). In this case the two contact elements will, by definition, have like pins, but since both elements are the same device, this is legal. However, if the coil (RELAY:A) and contacts (RELAY:B) both contained a pin with the same pin name, this would be an error.

Solution:

Re-make one or more of the devices that make up the multi-element device such that its pin names are unique (i.e. decompose the device, reannotate the pins and re-make the device). Ensure you say ‘yes’ to update the existing devices in the schematic when prompted before re-starting the Visual Packaging Tool.

Warning : Bus pin ‘x’ of device ‘y’ has no range.

Where ‘x’ is the name of the bus pin and ‘ y’ is the name of the device.

Cause:

You have used a bus pin for which there is no range specified. Each bus pin must have a range specified in order that you can tap off the bus and that you can correctly package the device.

Solution:

Warning: Packaging ‘x’ specified in 'y’ is different to packaging specified in 'z’

Where ‘x’ is the name of a packaging and ‘y’ and ‘z’ are two devices.

Cause:

This occurs only with legacy devices only and means that you are packaging a multi-element device where different elements specify the same package name (e.g. DIL40) but the pinouts (which specify the pin numbering) for each element is different. This is ambiguous and only one of the pinouts (sets of numbering) will be used.

Solution:

You can safely continue from this warning but be sure to double check that the pin numbering for the named packaging is correct in the Visual Packaging Tool.

Warning: Device 'x’ was not found in any library.

Where x is the name of a device that was not found.

Cause:  

The device you are trying to package cannot be found in any of the ISIS libraries. This may be because you have not created the part (i.e. the schematic has been passed to you from another user who has created the part in his libraries) or that the location of the library containing the part is not included in your system path.

Solution:

This warning can in general, be safely ignored. Its purpose is to indicate that if you subsequently bring in to play the original library containing the original device, you will have two instances of the same device in two different libraries. It is good library discipline to ensure that a device only occurs in one library.

Warning: Device 'x' was found in a read-only library 'y'.

Where ‘x’ is the name of the device you are packaging and ‘y’ is the name of a device library that is set as read-only.

Cause:

The device for which you are trying to assign packages exists in a library that is read-only. This is either because it is in a library supplied with the software, because you have specified one of your own libraries to be read-only, or because your user permissions prevent you from writing to the library.

Solution:

The purpose of this warning is to indicate that if you now store the part in a writable library, the same named device will be in two different libraries and this will may lead to ambiguities later on.

At the stage of getting the warning message it is probably best to immediately store the newly packaged device in any suitable writable library and then resolve the issue as follows:

  • If the original part exists in one of  the system libraries (i.e. a library supplied with the software) then use the Library Manager (launched from the Library menu) to change the name of the newly packaged device such that its name is unique.
  • If the part exists in one of your own user libraries which is set to read-only then use the Library Manager (launched from the Library menu) to temporarily remove the read-only setting on the library and to then move the part from the library you saved it in to your own library and then restore the read-only setting.
  • If your access permissions prevent you from writing to the library you will need to contact your Network Administrator to resolve the issue.

Bear in mind that it is important to maintain Library Discipline to avoid future complications.

You should always avoid having the same named library part in two or more libraries to avoid ambiguities.

You should never update parts in the system libraries (those supplied with the software as these may be overwritten by a future update of the software.

Warning: Device 'x' was found in a different library (y) to other tagged devices.

Where ‘x’ is the name of the device you are packaging and ‘y’ is the name of a library.

Cause:

You are attempting to package a multi-element heterogeneous device where not all the devices that make up the heterogeneus device exist in the same library. For example, if you are packaging a relay, where the coil exists in one library and the contacts are in another, then you will get this warning message.

Solution:

Use the Library Manager (selectable from the Library menu) to move the element(s) such that all elements are in the same library and are not duplicated in any other library. You can then safely package the device.

Warning: Device 'x’ was found in several libraries.

Where x is the name of the device you are packaging.

Cause:

The device you are trying to package exists in more than one library. This is either because you have created the device more than once and placed it in a different library each time, or because you have altered a device that exists in the system libraries (those supplied with the software) and placed it in one of your own libraries without using a different name.

Solution:
  • If the device exists in more than one of your own libraries you should either delete the device from one library or, should the devices be different in appearance or functionality, rename the devices via the Library Manager (selectable from the Library menu).
  • If the device exists in one of the system libraries and also in one of your own libraries you should rename the part in your library such that it has a unique name.

You can then safely package the device.
