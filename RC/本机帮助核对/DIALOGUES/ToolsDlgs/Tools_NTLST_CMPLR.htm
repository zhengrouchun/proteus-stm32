Netlist Compiler

Overview

This dialogue allows you to manually compile a netlist for the current schematic. If you are working with the ARES Layout software you should use the automatic netlisting method (Netlist to ARES command on the Tools Menu. Typically you would use this dialogue if you have designed the schematic in ISIS but are laying out the PCB in a different PCB package.

Do note that it is almost certain that the name of PCB footprints will be different in a foreign PCB package to that given in the ARES Layout software. This means that you will need to manually match the PCB footprint names on import to the PCB software if you are working in this way.

Options

Output

Specify whether you want to output the netlist to a file or to the netlist viewer.

Mode

Specify the type of netlist that you wish to generate. A logical netlist contains pin names whereas a physical netlist contains pin numbers. A more subtle effect is that in a physical netlist, the elements of multi-element parts such as the 7400 will be grouped (appearing, for example, as U1) whereas in a logical netlist they are kept separate (appearing, for example, as U1:A, U1:B, U1:C, U1:D). A logical netlist will generally be used for simulation whilst a physical netlist is best suited to PCB design. Transfer mode is used in specialist applications of ISIS only.

Scope

Specify the scope for the netlist. The default scope is the whole design. Current scope restricts the netlist generator to just the current sheet. This is generally used when you wish to extract the netlist from a child sheet - perhaps a daughter card which is to be represented as a layout in ARES, but which is part of a larger design that needs to be simulated whole. It is also possible to create a 'virtual test jig' by having a parent sheet which contains circuitry to simulate the components on the child sheet.

Depth

Specify the depth of the netlist. The default mode is to flatten the design. In this case objects with sub-sheets will be replaced by their implementation. If the netlist is not flattened then this replacement will not occur and objects with sub-sheets will appear as-is in the partslist and netlist. The most common reason for not flatting a design is if some components have attached child sheets representing their simulator models, but you wish to produce a purely physical netlist for PCB design. Note that sheets specified as non-physical will not be flattened for PCB design, irrespective of this setting.

Format

Specify the desired netlist format. Context Sensitive help is available on each option.

  • SDF - Specify the SDF netlist format. SDF (Schematic Description Format) is  the native Labcenter format - used by PROSPICE, ARES and any future Labcenter EDA products. Also very easy to read in and process to other forms. Contains all textual/connectivity information contained in the DSN file. Use Physical mode for ARES.
  • Eedesigner - Specify the EE Designer III netlist format. The user property PACKAGE is used for the package name. Use in Physical mode.
  • Multiwire/ Eag - Specify the Multiwire netlist format. Also used by EAGLE PCB design.File format does not contain packaging data. Use in Physical mode.
  • Spice - Specify the SPICE netlist format, also ideal for P-Spice. The ground net will be node 0, unnamed nets start at 1000; numeric net will be fed straight through. The file SPICE.LXB can be re-named to SPICE.LIB to obtain a set of SPICE compatible models. Use in Logical mode. Do not use this format for creating PROSPICE models – use the normal MDF output from the Model Compiler – it is far more flexible.
  • Tango - Specify the Tango netlist format, also used by Protel and others. A good general purpose format. Use in Physical mode.
  • Vutrax - Specify the VUTRAX netlist format.
  • Boardmarker - Netlist format for Tsien Boardmaker II. The user property PACKAGE is used for the package name. Use in Physical mode.
  • Futurenet - Netlist format used by Dash design tools. Also popular for general purpose netlist transfer. Use Physical mode for Pin List, Logical mode for Net List.
  • Racal - Specify the RACAL netlist format. Used by RedBoard, CADSTAR etc. Two files are created with CPT and NET extensions. The user property PACKAGE is used for the package name. Use Physical mode.
  • Spice - Age - Specify the SPICE-AGE netlist format for Those Engineers analogue simulator .The file SPICEAGE.LXB can be re-named to SPICEAGE.LIB to obtain a set of SPICE-AGE compatible models.
